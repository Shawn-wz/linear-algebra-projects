# 线性方程组求解器

用高斯-约当消元法解线性方程组 A x = b，并给出解集的完整描述：唯一解、无穷多解（特解加零空间基）、无解。

## 输入输出

输入第一行是行数和列数，之后每行是系数与常数项：

```
3 3
2 1 -1 8
-3 -1 2 -11
-2 1 2 -3
```

输出四种情况之一：

```
The solution exists and is unique.
Solution: ( 2 3 -1 )T

There is no solution.

Invalid input.
```

无穷多解时会先给一个特解，再给零空间的基，例如方程组 `1 3 / 1 2 3 6` 输出

```
There are infinitely many solutions.
Solution: ( 6 0 0 )T + x2 ( -2 1 0 )T + x3 ( -3 0 1 )T
```

第一个括号是特解，之后每个括号是零空间的一个基向量，自由变量取 1、其余取 0。特解依赖于消元过程中的取法，不唯一；基向量由零空间本身决定。

## 第一版

这是项目的主体，`linear-equations-solver.cpp`，239 行，手写完成。

### 思路

整体是高斯-约当消元：先把增广矩阵化成简化行阶梯形，再从最终矩阵的形状读出结论。

**第一步，前向消元（23–73 行）。** 从上往下处理每一行，每轮做四件事：

1. 从当前列开始往右找第一个非零列，它就是这一轮的主元列。找的办法是逐个候选列扫描它下面的所有行，取绝对值最大的那个元素来判断这一列是不是零。
2. 在这一列里选绝对值最大的行作为主元行，与当前行交换。这一步是为了让除数尽量大，减小舍入误差。
3. 把主元行除以主元，使主元变成 1。代码里只除主元之后的部分（`startj + 1` 起）和常数项，再把主元位置直接赋成 1，省掉几次除法。
4. 用它消去下方所有行在主元列的元素。

如果某一轮再也找不到非零列，说明剩下的行全是零行，直接结束。

**第二步，回代（75–111 行）。** 从最后一行往上，对每一行重新扫描一遍，找到它第一个非零元素所在的列，再用它消去上方所有行在这一列的元素。走完这一步，每个主元列上只有一个 1、其余全是 0，矩阵才是真正的简化行阶梯形。

**第三步，判断与输出（113–235 行）。** 扫描整个矩阵：

- 某行系数全为零而常数不为零，说明出现了方程 `0 = 非零数`，方程组无解；
- 非零行的个数等于列数，说明每个未知数都被主元确定，有唯一解，此时常数项就是解向量；
- 否则就是无穷多解。此时主元列对应主元变量，其余列是自由变量。程序输出一个特解（把自由变量全取 0），再为每个自由变量输出一个零空间基向量（该自由变量取 1、其余取 0，主元分量取约化矩阵该列的相反数）。

### 优点

- **算法本身是对的。** 它确实把矩阵化成了简化行阶梯形，三种情况的判断也成立。这一点后面三个版本一个字都没有改。
- **输出了完整的解集。** 无穷多解时不只说一句"有无穷多解"，而是给出特解与零空间的基，等于把整个解集写出来了。
- **有选主元。** 从一开始就实现了部分主元法，不是拿对角线元素直接除。
- **零依赖**，只用了 `iostream` 和 `swap`。

### 缺点

- **判断零用的是绝对阈值 `1e-7`（第 5 行）。** 这个数和数据的量级无关，于是把整个方程组乘一个正数之后，秩甚至解的个数都可能改变。测试脚本的 `-ScaleCheck` 在 66 项检查里抓到 5 处失败，例如乘以 `1e-6` 后 `25_small_coeffs_4x4.txt` 的解从一个变成五个。
- **主元列找了三次。** 前向消元找到 `startj` 之后没有保存，回代和判断时又各自扫描一遍矩阵重新找。信息其实一直在手里。
- **两段消元代码几乎重复。** 前向消元消下方、回代消上方，除了循环范围，剩下的字字相同。
- **没有输入检查。** 尺寸超过 102 或者数据非法时不会报错。用非数字的输入试一下，程序照常输出"有无穷多解"，给出一个错答案而不是拒绝回答。
- **输出精度默认只有 6 位有效数字。** 几个用例的相对残差因此停在 `5e-7` 量级，而其实还有 15 位的余量（对照：第一版最差相对残差 5.1e-7，第四版 5.5e-16）。
- **全部逻辑都在 `main` 里**，239 行没有函数边界，没有一段可以单独测试。
- **判定无解的代码写了两处**（第 91–99 行和第 129–136 行），同一个判断重复了两次。
- **`nonzeroc` 与 `nonzeror` 只差一个字母**，一个指列一个指行，读的时候容易看错。

### 小结

第一版的核心思路没有问题，缺点集中在数值、防御和结构三个方面。后面三个版本改的都是这些，算法本身没有动。

## 后续版本

以下版本以及全部测试均由 DSH 编写，第一版保留不动，作为对照。

**第二版（simplified）**：把"找主元"从三处收敛到一处，两个消元循环合并为一个函数。逻辑等价，代码变短。

**第三版（robust）**：修掉第一版里几个实际存在的问题。

- 判断零的阈值改为相对数据量级（原先固定 `1e-7`，整个方程组乘一个正数后解的个数会改变）；
- 增加输入检查，尺寸或数据非法时输出 `Invalid input.`；
- 输出精度由默认 6 位有效数字改为 15 位；
- 矩阵与常数向量收进 `struct System`，不再用全局变量。

**第四版（structured）**：只做函数边界，逻辑与第三版逐字等价。`main` 从 201 行减到 35 行，消元、矛盾判定、自由变量划分、两种输出各自成为函数。总行数反而更多，因为增加了类型定义和注释。

## 测试

测试脚本用精确整数消元（Bareiss 算法）算出每个用例应有的结论，不硬编码期望值，再加对解本身的检查：唯一解验证 A x = b，无穷多解验证特解满足方程、基向量落在零空间、个数等于 n − rank 且线性无关。脚本还检查输入异常的拒绝行为。

运行：

```powershell
pwsh -NoProfile -File tests/run-tests.ps1 -Source linear-equations-solver-structured.cpp
pwsh -NoProfile -File tests/run-tests.ps1 -Source linear-equations-solver-structured.cpp -ScaleCheck
```

`-ScaleCheck` 会把每个方程组整体乘以若干倍数，解集不变，因此结果也不应改变。第一版这项有 5 处失败（乘 1e-6 后解的个数都变了），第三、四版全部通过。

当前结果：33 个用例全部通过，最差相对残差 5.5e-16。
